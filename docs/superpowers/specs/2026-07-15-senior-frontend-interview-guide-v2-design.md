# 高级前端面试指南 V2 设计规格

**状态：** 已确认
**确认日期：** 2026-07-15
**交付形式：** Markdown only

## 1. 背景

现有《高级前端开发工程师面试指导》覆盖面广，适合作为完整题库和历史参考，但不适合作为一小时面试前的主复习材料：P0 数量过多，事实标签混合了候选人经历、源码证据、通用原理和设计提案，STAR 事件也缺少独立的真实性边界。

V2 不替换、不重写现有文档，而是在 `docs/interview/v2/` 新建一套更短、更可执行、可按 JD 切换的 Markdown 文档。

## 2. 目标

- 把面试当天必须掌握的主问题压缩到 24 个 P0。
- 区分“本人真实经历”“简历陈述”“源码证据”“通用原理”“设计提案”和“仍需本人补充的 STAR 细节”。
- 分离作战手册、STAR 故事、扩展技术题库、当天速查和 JD 定向路径，避免单份文档同时承担所有用途。
- 明确 Mint Forest 线上产品经历与当前本地作品集演示的边界。
- 对 React、Next.js、EIP-5792、EIP-7702 等内容增加版本基线，避免把当前规范倒推为历史项目事实。
- 让 10、30、60 分钟三种复习窗口都能直接执行。

## 3. 非目标

- 不修改现有 Markdown、DOCX 或 DOCX 生成脚本。
- 不生成新的 DOCX、PDF 或其他二进制文档。
- 不修改应用代码、依赖、构建配置或 Mint Forest runtime。
- 不虚构线上事故、量化结果、管理人数、项目职责或未在材料中确认的技术使用情况。
- 不把通用设计答案包装成候选人已经落地的项目经验。

## 4. 文档结构

| 文件 | 职责 |
| --- | --- |
| `docs/interview/v2/README.md` | 说明使用方法、事实标签、版本基线和新旧文档关系 |
| `docs/interview/v2/01-面试作战手册.md` | 24 个 P0 主问题，提供短答、展开、证据边界和追问 |
| `docs/interview/v2/02-真实项目与-STAR-故事库.md` | 汇总可确认项目事实，并提供 8 个不虚构的 STAR 故事槽位 |
| `docs/interview/v2/03-高级前端技术题库.md` | P0/P1/P2 扩展题库、答题检查点和版本说明 |
| `docs/interview/v2/04-面试当天一页速查.md` | 面试前可直接朗读和扫描的答案、数字、边界与反问 |
| `docs/interview/v2/05-JD-定向复习路径.md` | 通用高级前端与 Web3 前端两条路线，以及 10/30/60 分钟计划 |

## 5. 事实标签

V2 统一使用以下标签，不再使用含义过宽的“已确认”：

| 标签 | 含义 | 使用约束 |
| --- | --- | --- |
| `[候选人确认]` | 候选人本人明确确认的职责、经历或结果 | 面试前仍应由本人复核措辞 |
| `[简历事实]` | 当前简历中存在的陈述 | 不能自动推导出更多责任或结果 |
| `[源码可证]` | 可由当前源码、配置或文档直接证明 | 只能证明实现或仓库状态，不能证明本人贡献 |
| `[通用原理]` | 框架、浏览器、协议或工程通用知识 | 不得说成“我在项目中就是这样做的” |
| `[设计提案]` | 面对假设场景给出的合理方案 | 必须使用“我会”“可以”而非“我做过” |
| `[待补 STAR]` | 需要本人补充时间、场景、动作、结果和证据 | 未补齐前不得作为真实事故或业绩回答 |

项目事实允许同时带多个标签，但每个句子必须能判断其证据来源。

## 6. P0 范围

作战手册固定为 24 个 P0：

- 个人定位与协作：5 题。
- 核心项目与职责：6 题。
- React、Next.js、性能与工程：6 题。
- Web3、数据精度与系统设计：7 题。

每题包含：问题、30 秒短答、90 秒展开、证据边界和高概率追问。短答用于首轮表达，展开只在追问时使用。

## 7. STAR 故事边界

故事库提供 8 个高频行为题槽位，但只预填能由现有材料支持的背景。时间、冲突对象、故障影响、个人动作、量化结果和复盘证据没有来源时，明确标记 `[待本人补充]`。

大整数精度只能作为技术风险与设计原则，除非候选人补充真实事件，否则不得写成已经发生过的线上故障。

## 8. 项目与版本边界

- Mint Forest 的历史线上产品经历与当前仓库中的本地交互演示必须分别描述。
- 当前仓库只能证明作品集版本的结构、交互和去链上化状态，不能单独证明历史线上职责或业务结果。
- 仓库当前使用 Next.js 15.2.6；题库可补充截至 2026-07-15 的 Next.js 16 术语变化，但必须明确这是当前学习基线。
- React Effect 的时序回答必须保留“交互触发时可能在浏览器绘制前执行”的例外，不能简化成绝对的绘制后执行。
- EIP-5792 的回答按当前规范关注 capability、batch、`version`、`chainId`、`atomicRequired` 和 `atomic` 状态；EIP-7702 只解释其授权机制和关系，不混为同一标准。

## 9. 验收标准

- `docs/interview/v2/` 恰好包含 6 个 `.md` 文件，不包含 DOCX。
- `01-面试作战手册.md` 恰好包含 24 个 `P0` 主问题。
- V2 不使用 `[已确认]`，所有事实和建议均采用明确标签。
- 原有三份 interview 文件相对任务开始前无差异。
- 文档不包含 `TODO`、`TBD` 或模糊的“待定”；需本人补充的内容统一写为 `[待本人补充]`。
- 所有外部参考链接使用可点击的完整 HTTPS URL。
- `git diff --check` 通过，Git scope 只包含本次设计、计划、V2 文档和必要的 `HANDOFF.md` 更新。
