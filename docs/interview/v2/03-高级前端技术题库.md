# 03｜高级前端技术题库

## 使用规则

这是一份查漏补缺清单，不是背诵稿。P0 的完整表达在 [面试作战手册](./01-面试作战手册.md)；P1 是目标 JD 高频扩展；P2 用于资深面试官深挖。每题先能说清运行模型，再结合真实项目；没有项目证据时明确说“这是我的设计判断”。

`[通用原理]` 会回答某项技术，不代表项目实际采用。`[源码可证]` 当前作品集的实现，也不等于历史线上项目使用了相同版本和架构。

## 版本基线

- 当前仓库：`[源码可证]` Next.js 15.2.6、React 19、Pages Router 为主。
- 学习基线：`[通用原理]` 截至 2026-07-15 的官方文档。
- Next.js 16 将 `middleware.ts` 约定更名为 `proxy.ts`；历史项目回答仍按实际版本说 `Middleware`。
- EIP 会演进。面试中先说明规范版本与钱包实现，不能把当前 EIP-5792 请求字段倒推为 1DEX 当时全部代码。

### React 易错点

- “`useEffect` 永远在浏览器绘制后执行”不准确。
- “加 `useMemo` 就能优化”没有测量与依赖成本，不构成 Senior 答案。
- Strict Mode 开发期额外 setup / cleanup 是检查机制，不是生产重复请求的理由。

### Next.js 易错点

- “App Router 一定更快”错误。收益依赖页面、数据、第三方库和 client boundary。
- “Server Component 不发送 HTML 到客户端”错误；它的组件代码不进入客户端 bundle，但服务端结果参与 UI 输出。
- 不熟悉 App Router 生产实践时，准确说迁移方法和风险，不伪造项目经历。

## 七、白板题答题框架

遇到“设计一个……”时按以下顺序，不要直接画组件树：

1. 明确用户目标、数据规模、链 / 端 / 钱包范围和一致性要求。
2. 写出核心状态与不可违反的业务不变量。
3. 画数据源、服务边界、缓存和 mutation 流程。
4. 把正常、空、加载、部分失败、取消、超时、刷新恢复全部纳入。
5. 再决定 React 边界、store、adapter、测试和可观测性。
6. 明确首版取舍、验证指标与后续扩展，不声称方案已在项目落地。
