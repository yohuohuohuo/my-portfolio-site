## 技术一句话

- **React Effect：** render 要纯，commit 改 DOM；`useEffect` 通常 paint 后，但交互触发时可能提前，布局测量用 `useLayoutEffect`。
- **状态选择：** 本地 UI 用 state，低频树级依赖用 Context，跨区域细粒度订阅用 Zustand，每帧 Canvas 数据用 ref / engine object。
- **App Router：** 当前项目是 Next.js 15.2.6 Pages Router；理解 App Router 和迁移方法，但不伪造大规模生产迁移经验。
- **hydration：** 服务端 HTML 与首次客户端 render 必须一致；时间、随机数、locale、`window`、storage 都是高风险源。
- **性能：** 先定义用户路径与预算，测量 LCP / INP / CLS、长任务与帧耗时，再归因和回归。
- **金额：** 最小单位用 `bigint`、大数或十进制字符串；不能中途转 `Number` 再提交。
- **交易成功：** 返回 hash / batch id 只是 submitted，不是 confirmed；超时也不等于链上失败。
- **EIP-5792 / 7702：** 前者是 Wallet Call API，后者为 EOA 设置持久代码委托；不能把 7702 说成批量 RPC。
- **Solana：** ATA 是标准 Token Account；V0 可引用 ALT 降低地址占用，但不消除计算、签名和 instruction 数据限制。
- **多钱包：** 先探测 capability，保守降级；批量结果逐项表达，避免总 toast 掩盖部分失败。

## ownership 红线

- 1DEX、Mint Blockchain：可以说前端负责人。
- NFTScan：只能说核心前端开发。
- 用户量、下载量、全站流量：只能作为产品规模证据。
- 当前 `/mint-forest`：本地作品集演示，不是仍在线的 Web3 产品。
- 当前仓库的 fixtures、去链上化、Vitest、Playwright：不能倒推为 2025 生产版原有成果。
- 大整数：没有真实事故证据前，只说风险与治理方法，不说造成过线上损失。

## 压力题安全句式

- **没有公开指标：** “这部分没有可公开或已确认的数据，我不编数字。我能提供职责、交付范围、技术复杂度和工程结果。”
- **没有做过：** “我没有这项大规模生产经验。相近经验是……；如果接手，我会先……并用……验证。”
- **团队成果：** “这个指标是团队和产品结果。我的个人 ownership 是……，可以继续讲具体实现与决策。”
- **版本不确定：** “这个行为依赖具体版本，我先按当前规范解释；项目当时的字段需要以代码和钱包版本为准。”
- **需要行为案例但未准备：** 不用技术原理冒充故事；换一个真实、可验证的事件。

## 面试反问（选 3～4 个）

1. 这个岗位入职前三个月最需要解决的具体问题是什么？
2. Senior 对方案、Code Review、发布和线上值守分别承担什么责任？
3. 前端当前最大的复杂度来自业务、性能、历史架构还是协作流程？
4. 团队如何划分 ownership，技术决策如何记录和复盘？
5. 质量 gate 包括哪些检查，生产问题如何告警、归因和回滚？
6. 如果是远程岗位，同步时段、任务验收和绩效依据是什么？
7. 岗位提到的 App Router / Web3 / 多端能力，目前是已上线主栈还是未来建设方向？
