# 05｜JD 定向复习路径

## 先判断岗位是哪一类

不要只看职位名称。把 JD 的“职责”和“面试考察”关键词各标一次，再选主路径：

- **通用高级前端：** React / Next.js、TypeScript、性能、复杂交互、工程化、组件或平台、团队协作是主体；Web3 即使出现，也只是加分项。
- **Web3 高级前端 / 前端负责人：** 钱包、EVM / Solana、交易、资产精度、多链、DApp、合约协作是硬要求，同时仍要求通用前端深度。
- **混合岗位：** 先用职责占比选择主路径，再从另一条路径补 3～5 个 P0。不要因为 JD 出现一个 `wallet` 就把全部时间投入协议题。

## 一、通用高级前端路径

### 10 分钟

1. 读 [当天一页速查](./04-面试当天一页速查.md) 的自我介绍、三个项目短答和 ownership 红线（4 分钟）。
2. 口述 P0-02、P0-03、P0-12、P0-15、P0-17，每题只说结论与一个证据（4 分钟）。
3. 从 JD 选一个最相关反问，确认目标公司与岗位名称（2 分钟）。

### 30 分钟

1. 完整练 P0-01～P0-05，重点是通用 Senior 定位、负责人职责与远程协作（8 分钟）。
2. 练 Mint Forest、NFTScan 两个项目：P0-08～P0-11，突出复杂交互、SDK 和发布工程化（8 分钟）。
3. 练 P0-12～P0-17，确保 React / Next.js / 性能都有 30 秒答案（10 分钟）。
4. 复核数字口径与 App Router 经验边界（4 分钟）。

### 60 分钟

1. 按 30 分钟路径完成一遍（30 分钟）。
2. 在 [技术题库](./03-高级前端技术题库.md) 中各选 2 题：React、Next.js、性能、TypeScript、工程化，共 10 题快速口述（15 分钟）。
3. 在 [STAR 故事库](./02-真实项目与-STAR-故事库.md) 练 3 个已补齐故事：紧期限交付、技术分歧、线上故障或远程阻塞（10 分钟）。
4. 用 JD 原词改写自我介绍最后两句，并准备 3 个反问（5 分钟）。

### 通用岗位的项目排序

1. Mint Forest：复杂交互、性能、多端、独立交付。
2. NFTScan：SDK、TypeScript、发布工程化、多产品交付。
3. 1DEX：负责人、状态建模和外部系统不确定性；少堆协议名，多翻译为通用工程能力。

## 二、Web3 高级前端 / 前端负责人路径

### 10 分钟

1. 读 [当天一页速查](./04-面试当天一页速查.md) 的自我介绍、项目数字和技术一句话（4 分钟）。
2. 口述 P0-06、P0-18、P0-19、P0-20、P0-21、P0-23，每题只说核心模型（4 分钟）。
3. 复核 1DEX 不负责的模块和 NFTScan 角色边界（2 分钟）。

### 30 分钟

1. 完整练 1DEX：P0-06、P0-07、P0-20、P0-21、P0-23、P0-24（10 分钟）。
2. 练 Mint Forest 与 NFTScan：P0-08～P0-11，说明真实规模和个人 ownership（7 分钟）。
3. 练 P0-18～P0-22：EVM / Solana、金额、状态机、5792 / 7702、ATA / V0 / ALT（9 分钟）。
4. 复核能力探测、部分失败、超时不等于失败和当前规范版本边界（4 分钟）。

### 60 分钟

1. 按 30 分钟路径完成一遍（30 分钟）。
2. 从技术题库 Web3 / 系统设计组选 8 题，并画一次“多链批量交易”状态与 adapter 草图（15 分钟）。
3. 从 React / Next.js / 工程化各抽 1 题，防止岗位面试只会答链（5 分钟）。
4. 练 2 个已补齐 STAR：一次线上问题、一次多角色或远程协调（7 分钟）。
5. 准备安全、上线责任、RPC / 钱包测试相关反问（3 分钟）。

### Web3 岗位的项目排序

1. 1DEX：EVM / Solana、多钱包、批量交易、负责人职责。
2. Mint Forest：完整 DApp 交付、Canvas 复杂交互、用户规模。
3. NFTScan：多链数据产品、开发者 SDK 和发布工程。

## 四、经验缺口的诚实答法

### JD 要求多年 App Router 生产经验

> 我目前可确认的大型项目经验以 Pages Router 为主，当前仓库也是 Next.js 15.2.6。我理解 Server / Client Component 边界、缓存与渐进迁移方法，但不会把这说成多年 App Router 生产经验。我的相近证据是复杂 Next.js 产品交付、client-heavy 交互和多环境发布；接手后会先从低风险路由建立 hydration、bundle、缓存和 E2E 基线。

### JD 要求 Vue，而近期主栈是 React

> 我的近期主栈是 React / Next.js，不会声称同等深度的近期 Vue 生产经验。可迁移能力是 TypeScript、组件状态、路由、数据层、性能和工程化；框架差异我会用一个真实业务切片验证，而不是只背语法对照。

### JD 要求 Node.js / BFF 深度

> 我承担过 Nest.js 接口开发和完整前端交付，但主要定位仍是前端。可以负责接口合同、鉴权、错误、缓存与可观测性协作；如果要求独立负责高并发后端架构，我不会假装已有同等经验。

### JD 要求纯管理

> 我的负责人经验是 3 人前端协作，并持续直接负责复杂模块。我擅长交付型 Tech Lead，而不是脱离实现的多人组织管理。如果岗位核心是大团队绩效、招聘和组织设计，需要确认职责是否匹配。

### JD 要求某个未使用的钱包或链

> 我没有必要把使用过的钱包名称扩写。相近经验是 EVM / Solana、多钱包 capability detection、adapter、交易状态和异常恢复。我会先验证 provider 标准、签名方法、链支持、错误模型与测试环境，再接入真实业务切片。

### JD 的业务指标要求很强

> 我会提供口径明确的产品规模和工程结果，但不把团队指标全部归到个人。个人价值用 ownership、关键决策、交付范围和可验证结果说明；没有公开收入、交易量或转化数据时直接说明没有。

## 五、面试前 JD 改写清单

只改以下位置，不重写整套答案：

1. 自我介绍最后一句：连接 JD 的前三项职责。
2. 项目顺序：把最相关项目放第一，不改变事实。
3. 技术词汇：使用 JD 的准确术语，但不新增未做过的经历。
4. 两个 STAR：选择与岗位风险最接近的真实事件。
5. 三个反问：验证实际职责、技术现状和成功标准。

如果无法把某个 JD 关键词连接到“项目事实、通用原理或设计提案”中的任一类，就把它视为真实缺口，不要临场包装。
